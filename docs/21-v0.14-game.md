# v0.14 五夜战役、主菜单与发布

本版替代v0.13的三阶段和课堂演示设计。打开默认网址进入主菜单，游戏正式名称仍是《最后一盏灯》。

## 入口与主菜单

- 开始新游戏：选择简单、普通或困难，从第一阶段的新营地出发；已有存档时先明确确认替换当前进度。
- 继续游戏：恢复本阶段起点，保留之前完成阶段的资源、设施、人物、分数与计时。继续不是战斗中途断点续播。
- 排行榜：分别查看通关总用时和综合得分，难度独立筛选；未连接API时明确显示未配置，不编造榜单或个人名次。
- 游戏背景：阅读黑雾、幸存者家园和守灯人的故事，也可观看开场后返回菜单。
- 操作指南：说明探索、施工、指挥、镜头、暂停、计分和重开规则。

移除`demo=1`课堂入口、预置演示阵地、底部演示按钮和新成绩的演示分榜。旧数据库演示记录作为历史数据保留，不混入版本3榜单。

## 灯塔与镜头

主战场宽1280，高502，从界面y94开始，地图改为右上浮层。镜头对准灯塔SVG图像中心`(768,480)`，投影位于战场`(640,345)`，而非把角色脚底或左侧地图区域当成画面中心。

默认锁定灯塔，入夜演出也保持中心。WASD或点击地图暂时解除锁定以便查看远处；C重新锁回。缩放以当前焦点为中心，取消世界边缘夹紧，避免缩小时灯塔被挤到左侧。金线内可施工，金线外是未开放区域。

## 本阶段重开与存档

阶段检查点在该阶段首次进入时记录：

- 当时的营地库存、阵地、守卫、武器和成长阶段。
- 已完成阶段的首胜摘要、探索计分、营救名单和三段累计时间。
- 当前地图种子；重开探索时重用种子。

“确认重新开始本阶段”会丢弃本阶段新增物资、施工、击杀、救援和用时，恢复检查点；先前完成阶段保留。新尝试使用新的提交UUID，避免和此前已提交的失败成绩冲突。取消确认则保留当前局。主菜单继续同样恢复阶段起点。

存档键`last-light.campaign.v2`保留营地；新增`last-light.stage-checkpoint.v1`保存阶段和成绩检查点。失败或已完成战役仍可由明确的重开操作恢复最后阶段，绝不自动复活。通关后主菜单不把已结束战役显示为待继续。

## 双排行榜与计时

评分版本3，游戏版本0.14.0。主排序时间是三段游戏内模拟进度：

```text
durationMs = phaseTimesMs.day + phaseTimesMs.base + phaseTimesMs.night
完整五阶段：base = 150000ms，night = 600000ms
totalDurationMs = 实际活动墙钟时间（附加展示）
```

探索时间含本战役全部探索次数。布防提前按Enter时仍按该阶段30秒计入；夜战只有实际推进的模拟秒进入计时。完整通关的布防、夜战固定750秒，因此极速成绩主要由探索用时决定。倍速减少实际等待，不改变相同模拟进度的主要用时。暂停、失焦、背包、指南、排行榜、结算与离线时间均不补算。

通关用时榜：游戏总用时升序、同时间得分降序、再按实际活动用时升序。综合得分榜：分数降序，再按游戏总用时升序；完全并列再按实际时间、提交时间、UUID排序。简单/普通/困难分别排行。未完整记录五阶段的结果进入挑战榜，保留真实已完成内容，不伪造旧阶段计时。

计分：每阶段首胜2000，全部通关再加4000；普通击杀每只5分，阶段上限120/220/340/420/520；Boss每只250，阶段上限1/2/5/5/6；守住阶段按灯塔比例最多1000、每名生还守卫100；探索击杀、搜刮、成功护送按既有上限加分。完整通关的效率奖励使用游戏总用时。前后端用同一个纯函数重算，仍不是服务器权威防作弊。

## 部署与后端

游戏发布地址：[GitHub Pages](https://liguanheng.github.io/SEAPP/)。仓库工作流`deploy.yml`需要实际触发，单独push不会自动更新网页。网站带`version.json`，可核对`gameVersion=0.14.0`、`campaignStages=5`。

按用户选择，本轮先发布游戏，在线排行榜后端稍后配置。未配置`VITE_API_BASE_URL`时单机探索、布防、守夜、重开、存档和成绩结算照常运行，提交/读取在线名次会说明未配置。没有将本地测试数据冒充线上排名。

之后部署现有Fastify/PostgreSQL后端，执行003迁移并配置Pages仓库公开变量`VITE_API_BASE_URL`再重新发布前端。001/002校验和保留，003增加五阶段、三难度、三段时间和实际活动用时，旧版记录保留并按评分版本隔离。
