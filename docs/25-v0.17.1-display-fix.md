# v0.17.1 显示稳定性修复

2026-11-01，基于`67bff2d`。版本0.17.1，评分规则6不变，困难模式、阶段成长和营地进度沿用原规则。

## 问题与修复

v0.17探索HUD仍保留`setScrollFactor(0)`，而独立UI相机通过滚动偏移补偿高分辨率缩放。两种定位方式冲突，使生命/体力条、物资栏、小地图、暂停、背包、回营摘要和按钮离开实际画面。游戏模型仍在运行，因此仅检查模型状态、按键或基地场景未能发现这个显示问题。

已在旧4K设置下本地复现并保存修复前截图；移除探索HUD的固定滚动设置，由独立UI相机统一定位。正常探索、暂停、背包、归来面板重新显示，鼠标可以点击进入基地，再从基地进入另一街区。

取消所有画质选择，统一固定1920×1080画布，逻辑布局仍为1280×720；文字独立使用2倍绘制精度。渲染像素数为旧4K档的四分之一，不再根据旧偏好提升到4K。启动时仅移除废弃的`last-light.display-quality`键，保留营地、阶段检查点、世界搜刮记录和已有成绩。

## 验证方法

新增`tests/browser/display-stability.spec.ts`：

- 分别预置旧ultra/high/standard设置，确认自动使用1080p、菜单无画质选择、营地原文保留。
- 在2551×1307大窗口、旧ultra偏好下，用真实截图的像素验证生命条与暂停/背包/回营面板实际可见；同时执行鼠标点击和镜头缩放。
- 首趟真实搜刮建材、救援工程师并护送返营；连续三次从街区回营，点击可见的进入布防按钮，再点击再次探索，核对街区确实轮换，最后点击完成布防进入守夜。

这组回归补足了此前只检查模型状态的缺口。其他现有探索、战斗、存读档、施工、镜头、阶段推进和排行榜场景继续回归，结果见 [验收记录](BACKEND_VALIDATION.md)。
