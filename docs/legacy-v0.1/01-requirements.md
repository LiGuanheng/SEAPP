# 《最后一盏灯》需求分析文档

版本：0.1（初稿） · 日期：2026-10-22 · 状态：选题与核心方向已确认，细则待试玩反馈

## 1. 背景与目标

本项目为软件工程课程个人项目。玩家扮演废土灯塔守护者，在有限资源下安排探索救援、设施建设、守备小队与灯光强度，抵御五个夜晚的丧尸感染者。交付可运行源代码、需求与设计文档、测试记录及后续可访问的部署地址，以真实 Git 提交记录展示迭代。

目标是实现一个规则清晰、可完整游玩、可测试和可扩展的小型游戏。当前需求来自用户讨论与课程要求截图；完整任务书尚未发布，课程具体评分项不作推断。

## 2. 用户与边界

| 角色 | 目标与操作 |
| --- | --- |
| 玩家 | 学习规则、探索建设、调整策略、完成一局、读取本地进度 |
| 课程评阅者 | 按说明运行项目，核对需求、设计、实现和测试之间的对应关系 |
| 开发维护者 | 调整数值，新增敌人、设施、事件及后续服务模块 |

本期为单人浏览器游戏，无登录和网络对战。运行数据保存在当前浏览器，不跨设备同步。后续候选：账号、云存档、每日挑战、在线排行榜、地图编辑器；是否纳入以正式任务书为准。

## 3. 核心规则

- 阶段：白天准备 → 夜间防守 → 黎明强化 → 次日准备；第五夜结束直接胜利。
- 灯塔初始耐久 100，材料 100，能源 75；耐久归零失败。
- 白天最多探索一次，三处地点分别偏向材料、能源和高风险混合补给。随机事件可影响收益或耐久，结果即时说明。
- 固定敌人路线和 12 个建造点；设施只能建在空建造点，不允许堵住路线。
- 设施：哨戒塔（均衡单体）、霜冻塔（减速）、爆破塔（范围伤害）。白天可建造、拆除（返还原价的 60%）、维修灯塔。
- 灯光三级。微光节能，标准均衡，强光增加射程与探索收益，同时吸引更多敌人。能源归零后按微光作战，提示玩家，不能无限透支。
- 夜间敌人分批进入，按路线前进；设施自动攻击。抵达灯塔的敌人消失并造成伤害。
- 玩家可支付 12 能源释放灯塔脉冲，对所有在场敌人造成伤害，冷却 18 秒。
- 每夜全部敌人被消灭或抵达灯塔且灯塔仍存活，判定守夜成功，发放补给并进入强化选择。
- 暂停与设置弹窗停止模拟；2×速度仅改变模拟速度。后台标签页自动暂停，避免离开页面导致失败。
- 战斗胜负只影响本局，不含永久角色养成。

用户补充方向后，本期加入以下规则：

- 敌人为普通感染者、疾奔感染者、重型变异体：分别偏均衡、速度和高生命/高突破伤害；生命随夜数增长，第二夜开始出现重型变异体。
- 探索可能获得燃烧瓶或震荡弹，并救回独特专家。首次探索保证工程师与 1 个燃烧瓶，后续每次独立有 65% 概率获得武器、60% 概率救援一位尚未拥有的专家；最多三位，不重复救援。
- 工程师使之后每次探索额外获得 8 材料；医生每次成功守夜后修复 12 耐久；队长使守备小队伤害增加 25%。
- 三个固定防区，每处可花 45 材料部署一个三人守备小队。小队独立索敌射击，距离 2.5 格，射击伤害 12、间隔 0.65 秒；当前为每队共享射击判定，三个队员提供视觉表现，非三个独立战斗单位。本期小队不可撤回，也没有士兵伤亡与装备养成。
- 燃烧瓶：全场立即受到 20 伤害，并在之后 4 秒受到每秒 12 的区域灼烧，期间进入区域的敌人也受影响；多次使用刷新灼烧时间，不叠加每秒伤害。震荡弹：全场 15 伤害，减速 55% 持续 5 秒；减速不与霜冻叠乘，也不会被较短的霜冻覆盖。
- 特殊武器仅在夜间有敌人时可用，按库存消耗一次，不额外耗能；这些伤害当前不受设施火力强化加成。
- 夜战采用俯视地图，加入感染者体型区分、小队枪火、范围爆炸、灼烧、漂浮余烬、迷雾和灯塔光束。宏大战役、兵种养成、多地图及首领战留待后续迭代。

## 4. 功能需求与验收

优先级：P0 为本期必须，P1 为基础体验。

| ID | 优先级 | 需求 | 可验证的验收条件 |
| --- | --- | --- | --- |
| FR-01 | P0 | 创建与重开游戏 | 新局恢复第 1 天及初始资源；已有进度重开需二次确认 |
| FR-02 | P0 | 白天探索 | 同一天最多一次；展示地点、收益与事件；资源不为负 |
| FR-03 | P0 | 建造与拆除 | 空位且材料足够才能建造；材料准确扣除；夜间不可建拆；拆除返还正确 |
| FR-04 | P0 | 灯光取舍 | 三级可选择；说明收益与成本；无能源时回落微光规则 |
| FR-05 | P0 | 自动防守 | 三类敌人沿固定路线前进；三类设施依射程和冷却攻击；漏怪扣耐久 |
| FR-06 | P0 | 应急技能与维修 | 技能受阶段、能源、冷却约束；维修仅限白天且不超过最大耐久 |
| FR-07 | P0 | 昼夜推进与强化 | 清空当夜所有敌人后才结算；每次最多选择一项强化；进入次日 |
| FR-08 | P0 | 胜负与统计 | 第五夜守住为胜利；耐久归零为失败；展示天数、击杀与分数 |
| FR-09 | P1 | 暂停与设置 | 暂停后敌人、计时和资源均不变化；支持音量和 1×/2×速度 |
| FR-10 | P1 | 本地存档 | 刷新后恢复准备、战斗或强化阶段；损坏或不兼容存档提示后新建；存储不可用时仍可玩 |
| FR-11 | P1 | 帮助与响应式界面 | 新玩家可查看流程；窄屏无水平溢出；建造可通过按钮和键盘完成 |
| FR-12 | P0 | 探索武器与特殊人物 | 首次探索提供可用武器与工程师；之后可救援其他人物，能力能影响实际规则；人物不重复 |
| FR-13 | P0 | 小队部署与协同作战 | 白天可在三防区花费材料部署；每防区不重复；夜间独立索敌、造成伤害 |
| FR-14 | P0 | 丧尸分型与特殊武器 | 三类感染者速度/耐久/伤害不同；燃烧与震荡实际影响战斗；无敌人不扣库存 |

## 5. 非功能需求

| ID | 要求 | 验证方式 |
| --- | --- | --- |
| NFR-01 | 构建后无运行时外部接口依赖；刷新不依赖服务端路由 | 生产预览与网络检查 |
| NFR-02 | 规则层不依赖 DOM，可在 Node.js 下测试 | 自动化规则测试 |
| NFR-03 | 对浏览器存储异常、无效操作、异常存档给出反馈 | 规则与浏览器测试 |
| NFR-04 | 桌面为主要交互场景，窄屏可操作；按钮有可访问名称与可见焦点 | 1440px 和 390px 页面检查 |
| NFR-05 | 目标为常见桌面浏览器平稳运行；模拟步长不高于 0.05 秒 | 固定步长实现与 Chrome 实测；其他浏览器待验证 |
| NFR-06 | 不收集身份或个人信息；存档有格式版本，导入前校验 | 代码与存档测试 |

性能为当前设备上的验证结果，不承诺未测试设备帧率；战斗数值以通关测试与用户试玩继续调优。

## 6. 主要用例

UC-01 准备防线：玩家进入白天 → 选择探索地点 → 获得资源 → 选择设施和建造点 → 可调光或维修 → 主动开战。异常：材料不足、占用建造点、重复探索时拒绝操作并说明原因。

UC-02 守夜：玩家开战 → 敌人分批进场 → 设施攻击 → 玩家可调光、释放脉冲或暂停 → 判定失败或守夜成功。暂停时不产生任何战斗进度。

UC-03 黎明：存活并清空敌人 → 显示本夜补给与三项强化 → 玩家选择一项 → 日数加一。第五夜结束显示胜利，无第六天。

UC-04 恢复进度：打开页面 → 校验本地存档 → 合法则恢复并暂停战斗，非法则提示并新建。存储不可用则切换为仅本次会话游戏。

## 7. 假设与待确认

用户已确认题材及总体玩法，并提出丧尸分型、探索获取特殊武器/救援人物、黄昏部署军队及更精美宏大的夜战方向。上述具体人物、库存、小队简化规则、视觉、数值与架构由 AI 提议并实现，尚未获得用户试玩确认。任务书发布后核对：文档模板、必需数据库或后端、部署平台、测试覆盖要求、AI 使用披露要求及提交频率。
