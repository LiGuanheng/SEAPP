# 部署说明

## 当前边界

本阶段交付本地可运行版本与静态构建，不表示已经发布线上站点。正式上线待用户试玩及任务书核对后进行。

## 静态构建

```bash
npm ci
npm run build
npm run preview
```

生成目录为 `dist/`。Vite 构建使用相对资源路径，支持 `/SEAPP/` 这样的子路径。页面无客户端路由，无需配置 SPA 回退。存档保存在访问站点的浏览器源内，从本地迁移到线上不会自动迁移存档。

## GitHub Pages 候选方案

仓库含 `.github/workflows/deploy.yml`，仅 `workflow_dispatch` 手动触发，普通提交不会自动发布。流程执行规则测试与构建，上传 `dist/` 并部署 Pages。

使用前由用户确认 GitHub 仓库 Settings → Pages 中允许 GitHub Actions 部署；在 Actions 中手动运行 Deploy Pages。以工作流实际返回的地址为准，不预先声称某个地址已可访问。

截图显示仓库是私有仓库。私有仓库能否使用 Pages 取决于账户/组织套餐，站点可见性也受配置与套餐限制；部署前以当前 GitHub 设置及官方说明核实。不要为部署擅自把仓库改为公开。如不满足条件，可保留私有仓库，选用支持静态目录的其他托管服务。

## 上线验收

首页资源加载正常 → 能建造与开战 → 刷新能恢复本域存档 → 无外部字体/素材请求 → 无控制台错误 → 手机宽度可操作 → 记录部署时间、对应提交和实际地址。
